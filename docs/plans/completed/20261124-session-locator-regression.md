不把当时的连接故障归因于会话定位，也不把“有进程、租约续期”当作“已开工”。普通重启不自动重放旧指令是既有行为；返修启动则需要新的返修提示。

## 修复范围

- 返修从本任务最新被要求返修的交付取得同机实际定位，直接打开工作树中的原会话文件。定位缺失或机器不符时停止该返修、保留排队状态，不猜测其他历史会话，也不挡住同机其他可执行任务。只剩无法定位的返修时，领取接口明确返回 `session_record_missing`，启动器记录警告。
- 启动器核对目录、文件、文件头中的会话 ID 与工作目录；失败时明确报告，不创建空会话或回退登记目录。
- 首次执行保留开工提示；返修保留读取任务和反馈的提示；普通重启、恢复不添加新的开工消息。
- 网页与普通 Pi 任务管理接口展示实际会话 ID。保留旧接口的尝试类型兼容，不把新的恢复状态强加给旧接口。
- 自动启动上报与显式工作现场记录有顺序约束。显式记录等待启动确认及其有限重试结束，避免取消恢复所需的加载确认；关闭旧运行时后不继续提交旧定位。

## 隔离真机回归

从仓库根目录，在项目要求的 Node 24 和 pnpm 版本下先安装锁定依赖、完成构建，再执行：

```sh
pnpm install --frozen-lockfile
pnpm verify
node scripts/smoke-session-locator.mjs /绝对路径/pi
```

脚本使用临时 Git 仓库及独立工作树、本机回环地址上的临时平台、临时 Pi 配置、独立 tmux socket 和确定性本地模型，不调用远端模型、不读取真实任务会话、不更改用户配置。完成或失败后清理自建进程及临时目录。

验证流程：

1. 首次启动在登记目录，真实 Pi 工具记录现场。
2. 用 Pi 原生会话切换进入 fork 到工作树的新会话，旧目录的 JSONL 保留不动。
3. 在平台发起重启，核对真实 Pi 加载的目录、ID、文件，以及网页和任务管理接口显示的 ID；重启前后用户消息数不变。
4. 分别临时移走会话文件和工作树，确认明确失败且不终止源 Pi、不回退。
5. 中断进程后发起恢复，确认仍回到目标现场，且不重放指令。
6. 从恢复尝试保存测试交付并返修，确认自动回到同一工作树和 JSONL，并新增返修提示。

本机 Node 24.22.3、pnpm 11.20.0、Pi 1.6.0 验证通过：

该测试验证真实 Pi、tmux、平台和扩展的本机链路，不覆盖 LaunchAgent 安装升级或 Pi Reach 连接。平台和启动器须配套更新：旧启动器不能解析新增的精确定位字段，新启动器遇旧平台的无定位返修会安全停止。原有恢复参数白名单保持不变；不支持的配置明确失败，不降级启动。

修复本身不等于已发包或部署；生产和用户级启动器需按既有发布流程另行授权更新。已落在错误现场的历史尝试不会通过扫描其他会话自动修复，仍需先核对并登记其正确现场。
