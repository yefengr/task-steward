# 待评估事项

本文件只收录尚未确认开发的候选，不维护进行中状态；确认开发后移入 [ROADMAP](ROADMAP.md)。候选来源包括[已归档首版技术方案第 9.3 节](plans/completed/20261112-initial-design.md#93-实施顺序)，不把历史建议顺序当作当前排期。分组和顺序依据 [CONTEXT 第 1、2 节](CONTEXT.md#1-定位使用者与问题)的产品定位。验收积压上限已移出：验收节奏由用户掌握，Steward 不设验收门禁。

## 定位核心缺口（按建议顺序）

1. Git 操作授权：取消扩展提示词中统一禁止推送和合入的规则，改为在开工单中写明授权范围，上限由项目规则决定；与第 5 项一并由任务台「[04] Git 操作规则、走 PR 项目的收尾与本地合并可选」讨论。削减 Steward 自身其他打断已确定开发，见 [ROADMAP](ROADMAP.md)。
2. 依赖调度与整批开工：任务先后关系与满足条件，前项完成后后项自动开始；用户在 Claude Code 或 Pi 会话中明确授权即可安排开始。不另设「计划」对象。
3. 开工前就绪检查：方案已在基准分支、目标明确、授权范围写清；Steward 只检查，不代为提交。
4. 交付后推进到下一步：发布、合并、继续讨论不再借用返修；集中显示需要我处理的事项，并能直达对应会话。
5. 走 PR 项目的收尾：记录 PR，PR 合并后清理工作树和分支；本地快进合并改为项目可选项。
6. Claude Code 讨论入口：在 Claude Code 中查看、创建、修改任务及依赖，并在用户明确授权时安排开始。
