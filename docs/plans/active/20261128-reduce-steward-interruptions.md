# 削减 Steward 自身造成的打断

## 目标与适用范围

按[产品定位](../../CONTEXT.md#1-定位使用者与问题)，提前安排的任务要能在后台连续执行，只在授权、可能丢失工作或影响他人现场时停下来问用户。本方案处理 Steward 自身的现场核对、讨论收尾、Git 归属和升级接续造成的提问，并精简扩展注入的规则。

Git 推送与合入的授权规则，以及验收后本地合并时基准分支被检出的处理，归任务台「[04] Git 操作规则、走 PR 项目的收尾与本地合并可选」，本方案不重复。事项状态只在 [ROADMAP](../../ROADMAP.md) 维护。

## 依据

2026-11-20 至 11-27 线上共 129 次提问，其中 18 次由 Steward 自身机制引起，按 0.4.1 主线代码逐类核对：

| 类别 | 次数 | 最近一次 | 当前 |
| --- | --- | --- | --- |
| 返修时要用户手动切换工作树或接回原会话 | 6 | 11-24 | 已基本解决：启动器按记录在原工作树和原会话启动，11-25 起未再出现 |
| 返修现场未登记、登记冲突或分支对不上 | 5 | 11-27 | 仍发生：未写代码的任务没有现场记录；分支正常变更也判为不匹配 |
| 只认一字不差的「结束讨论」 | 2 | 11-27 | 仍发生 |
| 待验收时不能追加交付 | 1 | 11-25 | 已解决：0.4.0 支持「仅补交付记录」 |
| 已取消任务的分支仍归原任务，新任务无法承接 | 3 | 11-27 | 仍发生：分支与工作树占用不区分任务是否已取消 |
| 主目录检出基准分支，开工前同步被挡住 | 1 | 11-27 | 仍发生 |

另有 2 次在升级 Steward 后要求用户重载或重启 Pi：Pi 1.6.0 会缓存同路径的扩展文件，`/reload` 不能可靠换到新版，而部署文档仍建议 `/reload`。

## 原则

1. **能由 Agent 判断的不问用户。** 只有涉及授权、可能丢失工作或改动他人现场时才提问。
2. **规则放进工具返回，不堆在提示词里。** 工具在调用不当时拒绝并说明下一步；提示词只讲任务、授权和项目规则优先。
3. **只核对真正需要核对的。** 现场核对用于防止返修写错地方，只对已准备专用 Git 工作树的实现任务严格执行。

## 方案

### A. 返修现场核对

- 上次没有准备 Git 的任务（只读、整理、原型等）返修时不要求现场记录，直接在启动器接回的原会话继续。
- 已准备 Git 的任务以 Git 准备记录中的工作树和任务分支为准；与当前会话一致即确认，不再另行比对手动登记的现场。
- 同一工作树内分支已变更且工作区干净时，Agent 记录实际分支后继续，并在进展中说明。工作树缺失、属于其他任务或有来源不明的未提交改动时才暂停提问。
- 现场登记改为在准备 Git、创建或切换工作树成功时由工具自动完成，提示词不再要求 Agent 单独登记。

### B. 结束讨论

- 用户在会话中明确表达结束，如「结束讨论」「结束当前任务」「就到这吧」，由 Agent 判断后登记结束请求、整理结论并交付。工作台「结束讨论」按钮保留。
- 交付前 Agent 先说明「将保存以下结论并结束」及结论摘要，不另行提问。误判时用户可以按已有流程续做。
- 已有结论、当前回合结束或无人回复仍不构成结束。

### C. 已取消任务的分支归属

- 任务取消时释放其对任务分支和工作树的占用，不删除分支或工作树，由用户处理。
- 新任务的目标或备注写明要承接的分支时，Agent 可以在该分支上准备 Git 并继续；平台不再以原任务归属拒绝。
- 不提供恢复已取消任务。取消是终态，需要继续时新建任务承接。

### D. 基准分支被检出时的开工同步

- 开工前同步基准分支时，若本地基准分支已检出在其他工作树且该工作树干净，直接以拉取到的远端提交作为起点，不更新本地分支、不改动该工作树。
- 远端与本地分叉、该工作树有未提交改动等情况仍按现有规则拒绝。

### E. 升级后的接续

- 部署文档和扩展提示改为：升级后正在运行的 Pi 需要重启才能加载新版，用工作台「重启 Pi 会话」或新开 Pi，不再建议 `/reload`。
- 启动器新拉起的后台 Pi 本来就加载新版，不变。

### F. 扩展提示词精简

- 开工消息以任务开头：启动器发给后台 Pi 的第一条消息写明是新任务还是返修，以及任务标题，再提示用 steward_task 读取目标、验收要求和授权；执行规则不再写在这条消息里。
- 按原则 2 把后台会话注入的规则压缩为任务先行、遵守授权与项目规则、按工具指引处理 Git 与现场、交付与讨论收尾四条，吸收原「扩展提示词优化」待办的范围。返修现场切换、现场登记时机、交付提交号格式等细节移到对应工具的返回和错误说明中。
- Git 推送与合入相关的表述由 [04] 调整，本方案只做结构精简，不改变其含义。

## 实现与验证

- A、C、D 涉及平台、扩展与共享接口，按项目规则验证所有直接消费者，覆盖未准备 Git 的返修、分支变更、取消后承接和基准分支已检出的真实 Git 场景。
- B 需覆盖多种结束说法、误判后续做，以及工作台按钮仍可用。
- E、F 以提示词回归测试和文档核对为主；F 不得删除已有安全边界，只调整表达位置。
- 完成后按线上提问复查：同类提问应不再出现，新出现的机制提问记入本方案或后续事项。
